# Adopt Claude Code's hook vocabulary as the canonical event model

handrail is a clean-room design, yet its Event model uses Claude Code's event names verbatim: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `SessionStart`, `SessionEnd`, `Stop`. The 2026-08 harness landscape sweep (docs/research/harness-landscape.md) found the Claude Code hook protocol is a de facto standard: Codex, Qwen Code, Factory Droid, OpenHands, Augment, and Crush clone it deliberately, and Copilot CLI ships compatibility aliases. Event names are user-facing vocabulary (rules are written against them), so inventing neutral names would force every user to learn a vocabulary no harness uses, while adopting the standard makes the primary adapter near-zero translation. The clean-room constraint was about not copying file formats, not about refusing a wire standard the field already converged on. The model is versioned: the v1 set is the six-event core every committed harness supports; wider rings can be added without renaming anything.

## Considered options

Neutral invented names (`before_tool`, `turn_end`, in the style of Gemini CLI's own vocabulary) were rejected: Gemini is the only major harness that departs from the Claude Code naming, and a neutral layer would add a permanent translation table between what users write and what every harness document says. Mirroring Claude Code's full 31-event catalog was rejected as the v1 set: only the six-event core maps onto both committed harnesses (Claude Code, Codex) and nearly all Tier 1 candidates, and harness-only events would make degradation the common case instead of the exception.

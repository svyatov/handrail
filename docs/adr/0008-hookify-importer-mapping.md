# The hookify importer converts mechanically, amends file_edit with content, and skips what it cannot express

`handrail import hookify [path]` is a one-shot converter from upstream hookify's `.claude/hookify.*.local.md` files into Project-personal rules (`.handrail/local/`). The mapping is mechanical: `bash` becomes `PreToolUse` + `kind: shell`, `file` becomes `PreToolUse` + `kind: file_edit`, `prompt` becomes `UserPromptSubmit`, `stop` becomes `Stop`; `all` (upstream's default when `event:` is omitted) is inferred from the condition fields and skipped when the fields span more than one event. Fields map `command` to `command`, `file_path` to `path`, `new_text` and `content` to `content`, `user_prompt` to `prompt`. This decision amends the canonical payload: the `file_edit` kind gains `content` (the new content being written), because content matching is the bread-and-butter file rule both for native authoring and for imports; the path field stays `path` as originally recorded. `regex_match` becomes `matches` with `(?i)` prepended (upstream compiles every regex with IGNORECASE) and each pattern is validated under RE2; string operators copy verbatim because upstream's are case-sensitive already. The `pattern:` shorthand expands using upstream's own field inference. Anything inexpressible (`old_text`, `transcript`, `reason`, non-RE2 patterns, unmappable `tool_matcher` values, ambiguous `all` rules) is skipped with a per-rule report naming the reason and the original path; nothing broken is ever written. The converted filename comes from the `name:` field, an existing target file is never overwritten (re-runs are safe), originals are never touched, and `enabled: false` survives conversion. Upstream semantics were verified against the plugin's engine source, not its docs.

## Considered options

The docs-only mapping guide (the scope ticket's escape hatch) was rejected: the formats align closely enough that every construct either maps mechanically or has a clean skip path. Writing `enabled: false` stubs for unconvertible rules was rejected: strict-at-sync means never writing an artifact that cannot work, and the skip report carries everything a hand-port needs. Fanning `all` rules out into one file per event was rejected: upstream's engine only fires such a rule where its fields exist, so inference recovers the real intent while fan-out manufactures rules the user never wrote. Naming the path field `file_path` (Claude Code verbatim) was rejected: per-kind fields were deliberately normalized so one name serves file_edit and file_read.

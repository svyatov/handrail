# Rules are one-per-file markdown with YAML frontmatter, strict at sync, loud at event time

A Rule is a single markdown file, `<rule-name>.md`, in the harness-neutral `.handrail/` directory: the matcher lives in YAML frontmatter and the message is the markdown body. The message is the product (multi-paragraph prose aimed at an agent), so it stays first-class prose instead of an escaped YAML scalar. Identity is the filename; there is no `name:` field. The matcher addresses the event model explicitly (`event:` from the six-event core of ADR 0002, optional `kind:` tool kind), conditions are an implicit-AND list whose entries may be one-level `any:` groups, and each condition names one canonical payload field with the operator as the key: `matches`, `contains`, `equals`, `starts_with`, `ends_with`, `glob`, each negatable via a uniform `not_` prefix. Regex is RE2 (the engine is Go, so no lookarounds or backreferences), case-sensitive by default with inline `(?i)` opt-in; `glob` supports `**`. Actions are `warn` (the default) and `block`; `enabled:` defaults to true; there is no templating, no `raw.` passthrough field access, no `pattern:` shorthand, and no format `version:` field. Parsing is strict at sync time (any invalid rule fails the sync with errors) and loud-fail-open at event time (an unparseable rule is skipped and the failure is injected into the agent's context, naming the rule). Upstream hookify's silent fail-open, where a broken guardrail quietly stops guarding, is the failure mode this stance exists to kill. When multiple rules match one event, every message is delivered labeled with its rule name, and one block makes the outcome block.

## Considered options

Pure YAML with many rules per file and TOML were rejected: both demote the message to an escaped string and lose per-file toggling and clean diffs. `ask` as a third action was rejected for v1: only Claude Code supports it natively, so degradation would make it unpredictable exactly where a user wanted a human gate. Sugar aliases (`on: shell`), a one-line `pattern:` shorthand, message templating, and `raw.` field access were rejected as second vocabularies or portability traps; each can be added compatibly if a real need appears. `.claude/handrail/` as the rules home was rejected because the canonical store of a cross-harness tool cannot live inside one harness's vendor directory.

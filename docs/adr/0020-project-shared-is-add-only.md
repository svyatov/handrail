# The Project-shared tier is add-only against Global; a tier's identity is its supply, not its path

A Project-shared rule may not shadow a Global rule. Identity is the basename, so the collision is the one the tier merge already computes, and the shared file is dropped rather than rejected: the Global rule stands, `check` and `sync` name both paths and the reason, `check --json` carries `dropped_by`, a `SessionStart` notice names the count, and the exit code stays 0, because the collision needs a Global file the repository's author cannot see and a hard error would fail a user on a repository they did not write and cannot fix. The shared tier is therefore additive: it may ship rules of its own, including stricter ones under names of their own, and may never replace or switch off one of the user's. This is stated as the refusal it is and never as monotonicity, because a wholesale copy carrying a narrower condition weakens exactly as thoroughly and RE2 offers no subset test; refusing the shadow rather than adjudicating the weakening makes the property sound instead of enumerable. Dropping a shared `enabled: false` stub can deny a call that previously passed; that block comes from a rule the user wrote, which is the condition ADR 0012 sets.

Project-personal carries no such restriction and is the escape hatch that makes the refusal cost nothing: a user who does want the repository's weakening writes one stub in a tier that outranks shared anyway.

Two further refusals close the same door. `agent_only: true` is refused in the shared tier whether it shadows or not, since a repository rule that injects into the agent's context without telling the human is the objection ADR 0019 raised one tier over; it errors at `check` and `sync`, while the hook path drops the field, which only makes the rule louder. And `.handrail/local/` is read as Project-shared, gated by Trust and bound by the add-only rule, when any path under it appears in the git index or when `.handrail` or `.handrail/local` is a symlink, because `.git/info/exclude` never applies to a path already in the index and a repository that commits `.handrail/local/` would otherwise ship every cloner an ungated, top-precedence tier. The check runs only where that directory exists. It reads `.git/index` in process and stops at the first entry past `.handrail/local/`, which index order puts near the top, so it spawns no process and costs microseconds at any repository size.

Nothing here constrains a write to a rule directory, so an agent with write access to the working tree still reaches every project tier, and one with write access to the home directory reaches Global. handrail's answer is a pair of handrail rules the add skill teaches, on `file_edit` paths and on shell commands naming either rule location, with `action: ask`: a `block` would stop handrail's own skills, which run as the agent, from ever writing a rule, and the human's approval of one write is the grant a relaxation needs. handrail neither ships (it ships no rules) nor hardcodes (ADR 0012) them.

ADR 0004 stands in every decision it made: tier locations, precedence order, engine-side merging at event time, one hook entry per event, wholesale shadowing with no field merging, and Trust gating the shared tier.

## Considered options

Enumerating the weakening fields, as `dcg` does (an allowlist of six field/value pairs applied once at load, dropping the layer when it only weakens), was rejected because it catches the honest weakening and no other: a copy of the user's rule under the user's basename with one unsatisfiable condition is an ordinary shadow under ADR 0004 and defeats any enumeration. Detecting the weakening statically was rejected on the same ground plus cost: regex containment is decidable but PSPACE-complete, RE2 exposes no containment, equivalence or intersection API, and the only two production systems that ship the check (AWS Zelkova behind `CheckNoNewAccess`, Cedar's `check_implies`) co-designed their policy language around an SMT encoding and still return "incomparable" as a real answer. Allowing the shadow and notifying, as an informed `handrail trust` that lists what the repository would replace before the grant, was rejected as a second escape hatch for something Project-personal already answers, and it goes stale on the next `git pull`; binding the grant to file content, as direnv and Nix flakes do, buys that back at the price of a registry keyed on content and a re-prompt on every edit. Claude Code's split, applying a repository's restricting directions immediately and gating only its granting ones behind a trust dialog that enumerates them, is the same design one level up and was rejected for the same reason. Constraining Project-personal alongside Project-shared was rejected: it buys nothing against an agent that can write the tier anyway, and costs the legitimate act of switching off one Global rule in one repository. Refusing a demoted `.handrail/local/` outright, rather than reclassifying it, was rejected because a committed file genuinely is repository-supplied and demotion needs no new concept. Running `git ls-files` for the supply check was rejected: it spawns a second process, costs 5 to 20 ms and grows with the repository, and needs git installed. Hardcoding a refusal of writes to `.handrail/` was rejected on ADR 0012 (handrail never invents a block) and because handrail ships no rules.

A channel for a repository to ask for a relaxation was rejected in both shapes. A request naming a rule cannot be written, since Global basenames are the user's own and handrail ships no shared ones; a request naming calls is an allowlist, needing an `allow` that outranks a `block`, and restores the authority this ADR removes behind a grant that would have to be bound to content. A housekeeping boolean on a Global rule letting repositories shadow it puts the authority on the right side but grants a wholesale, unadjudicated replacement in every trusted repository when the need is one, and still leaves the repository guessing the basename. Project-personal already has the scope, the author and the precedence; the add skill writes a narrow shadow there.

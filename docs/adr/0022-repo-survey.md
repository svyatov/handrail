# Rules are proposed from the repository by a third skill, on demand, from a closed signal list

handrail ships no rules, because guardrails are individual to a repo and a person and a rule pack is someone else's, so a fresh install guards nothing. The replacement is the Surveyor: `/handrail:survey`, a skill that proposes rules from facts the repository states, and `handrail survey`, a command that finds those facts. A repo signal fixes every literal in a rule's matcher and never its action, its tier, or whether the rule should exist, so the Surveyor proposes and the user decides, per rule, exactly as with the Analyzer (ADR 0007).

The command prints facts and no rules, because the probes are deterministic and their cost bound (never list the tree, never read a lockfile) must be code rather than a prompt instruction; the skill turns facts into drafts and reads repo prose itself, which is the one part needing a model. The command finds signals by named stats and by matching patterns against `.git/index`, read in process with the same reader the Project-personal supply check uses (ADR 0020), so it spawns no git and needs none installed. It opens no file but the index and the instruction files. Where a signal needs a file's contents (`.gitignore`, `package.json`, a Taskfile or Makefile, a workflow, `.mcp.json`), the command lists the path and the skill reads it: those formats need either a parser handrail does not carry, full YAML and two Makefile dialects, or a model's reading of what a target runs, and a read set the command names keeps the cost bound in code.

The signal list is closed, and it lives in the spec (section 12) because its ids are the command's output: a signal enters by amendment with a replay against a real payload and a near-miss, never by the model's judgment in a session, because a proposal the user rejects costs more trust than one never made. With no incident to replay, each rule is verified by two replays built from the repository: the literal the signal found must match, a real neighbouring file must not. Rules land enforcing; trial is the user's answer, not the skill's proposal. The Surveyor proposes guards only: a repository signal never proposes relaxing a rule, even when its literal collides with one, because the repository is a stranger and a relaxation starts from a block the human saw.

Repo prose is a stranger's words in a cloned repository, so the skill writes every rule body and quotes the prose only as evidence: copying it into a body would let a hostile `CLAUDE.md` speak to the agent with handrail's authority.

When asked, the Surveyor also reads the user's own instruction files, which are the user's words rather than a stranger's and so suggest the Global tier. The bar is the same with one part made explicit: a matcher never fires on an act its sentence allows, so a sentence with an exception no matcher can see is dropped. The file is never edited, because the sentence is what the agent reads before it acts and the rule stops only the attempt. A file's class is computed by `handrail survey` from its supply, as a tier's is (ADR 0020): a tracked `CLAUDE.local.md` is repo prose, and an imported file is classed by where it lives, not by the file importing it. A repository's file is not followed out of the repository, though: its import of a path outside the Project root is not listed, because the file would be classed as the user's, and a cloned `CLAUDE.md` importing `@~/.aws/credentials` would then put the user's secrets on the Surveyor's reading list as the user's own words.

## Considered options

A mode of `/handrail:analyze` was rejected: ADR 0007's tuning job lives there because its signal joins the log and the transcript, and a repo pass reads neither, while one description serving two triggers makes both trigger less reliably. A no-argument run of `/handrail:add` was rejected because the model cannot see it when choosing a skill. An unprompted pass at `SessionStart` was rejected: a hook cannot run a model, so it could only inject an instruction to the agent to write rules, which is ADR 0007's nudge and a bad precedent under a prompt-injected agent; the fresh install says once, to the human, that the skill exists. Trial by default was rejected because it recreates the empty install this skill exists to fix, and every proposal already carries per-rule consent. An open signal list was rejected as the path to plausible, unwritable proposals. A registry of declined proposals was rejected as new state for a rare act. Writing into the Project-shared tier was rejected because it is committed and trust-gated, and the user may not own the repository. Spawning `git ls-files` for the pattern probes was rejected: the index reader already exists for the supply check, and the binary spawns no process. Parsing the content signals in the command was rejected: it needs a full YAML parser, a second runtime dependency (ADR 0011) for one command off the hot path, and still leaves what a Makefile target runs to judgment.

Leaving the user's own instruction files out was reversed: they are the strongest consent a proposal can have, and transcribing them is the same act on different files. The Analyzer was rejected as their reader, because those files are already in its context and an incident that breaks one is already a signal it reads. Replacing the sentence with the rule was rejected: the sentence prevents the attempt, works where handrail does not run, and is not handrail's file to edit. Reading them on every run was rejected: with no record of declines, a declined Global proposal would return in every repository surveyed. The managed policy file was rejected as an administrator's words.

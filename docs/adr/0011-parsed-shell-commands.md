# A shell command is a parsed program, and every reading of it is a candidate

handrail parses the `command` field with `mvdan.cc/sh/v3/syntax` and evaluates a condition against the whole command line plus, for every command the program runs, its verbatim source text and an unquoted form. How a condition reads these values, `not_` included, is ADR 0024. This is strictly additive: every rule that fires under the string-comparison model still fires, so the change lands without a migration. Leading environment assignments come off with the parse and are kept as their own level (ADR 0024). A fixed list of Wrappers is stripped, with both forms kept as candidates: `timeout`, `time`, `nice`, `nohup`, `stdbuf`, `command` (not `command -v`), `builtin`, `noglob`, `sudo` and `env`, and the runners that run a command on this machine, `exec`, `doas`, `setsid`, `flock`, `watch`, `xargs`, `find -exec`/`-execdir`/`-ok`/`-okdir`, `mise exec --`, `direnv exec DIR` and `devbox run`, each with a fixed flag table. Parsing is bash-dialect for every shell call, PowerShell included, as a declared approximation. Error recovery is on, so a truncated command still yields the commands it does contain; a hard parse failure yields none, keeps the whole line as a candidate, and records that handrail could not read the input, which is the give-up signal ADR 0012 owns. The files a command names become payloads of their own (ADR 0014).

The boundary: handrail reads shell **syntax** and never shell **semantics**. It follows a command into another program when the program is a listed shell or Wrapper and the command is literal in the call, so `bash -lc 'rm -rf /'` yields `rm -rf /` and `setsid rm -rf /` yields it too. The shells are `sh`, `bash`, `zsh`, `dash`, `ksh`, `mksh` and `su -c`, read through a `-c` flag cluster, a literal `eval`, and a literal heredoc or herestring; `watch` and `flock -c` pass their command to `sh -c`, so their argument is read as a script. It does not expand variables, resolve globs, read files, or follow data between commands. Code a listed program runs that the call does not hold literally is declared unreadable, not guessed at. Re-parsing stops at four levels. A program joins a list only if it runs, on this machine, a command named in its own arguments, so remote runners (`docker exec`, `kubectl exec`, `ssh`) and the package runner `npx` stay out.

## Considered options

Documenting the weakness and teaching `contains` was rejected: it leaves the default reading as the one that produced the original compound-command bypass, so the safe form is the one you have to know to ask for. Segment-aware splitting on shell operators was pursued for six rounds and rejected on its own cost curve: quoting, then substitution inside double quotes but not single, then subshell grouping, then process substitution, then control-flow keywords, each a correctness bug found one at a time, and the one prototype written already had a real one that a test caught. Writing a POSIX parser by hand or binding tree-sitter was rejected as the question framed it, and that framing was the error: a pure-Go stdlib-only parser exists, is 9,123 lines, costs 2.7 µs at worst, and is correct on every case. Adding `command_line` as a whole-line field was rejected once union made its only motivating case work on `command`. Vendoring the parser into `internal/` was rejected: it keeps the go.mod line clean at the price of owning 9,123 lines of forked parser with no upstream security path, which for a security tool is the worse half of both options. Ceilinging handrail's own matching to whatever the weakest native matcher does was rejected: with one rule serving many harnesses it means handrail sees less the more harnesses it supports. Refusing runners as a category, the first answer here, was reversed. Its reason, that a runner changes what the real command is, holds for `docker exec`, `kubectl exec` and `ssh`, which stay out, and fails for `setsid`, `flock`, `find -exec` and the rest, which run the command on this machine. Leaving nested shells opaque was rejected because the parser already hands their code over as a literal string, so reading it crosses no line this decision drew, and under the adversarial threat model `bash -c` is the cheapest bypass of every anchored rule. A separate field for inner commands, so that a rule opts in to reaching through, was rejected: it makes the safe reading the one you must know to ask for, which is how the compound-command bypass happened.

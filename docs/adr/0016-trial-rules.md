# A rule can be put on trial, per rule, and a trial delivers nothing

A guardrail you do not yet trust is the normal case, not the exception: rules arrive by proposal, and the honest first reaction to a new one is wanting to see it fire before it can stop you. handrail already has a gentler action, `warn`, so the obvious answer is to trial a rule as a warn and promote it to `block` when confident. That answer is wrong, and the reason is the whole justification for this decision. A warn injects its message into the agent's context, so the agent reads the rule and steers around it. The trial changes the traffic it was taken to measure, and a quiet week afterwards proves nothing: the rule may be well-judged, or the agent may simply have been told. `trial: true` is the only shape in which handrail watches a rule without the rule being seen.

Trial is per rule. A global mode is far cheaper to build and is the wrong trade for this job: to try one unproven rule you would stop enforcing every proven one, which is the moment the guardrail was for. Per tier is the same objection with a smaller blast radius. The field agrees and consistently: six of the eight policy engines surveyed attach the non-enforcing decision to the individual policy (Gatekeeper's `enforcementAction: dryrun`, Kubernetes' `validationActions: [Audit]`, Kyverno's `failureAction: Audit`, Sentinel's `advisory`, ESLint severity, Semgrep's Monitor), and the two exceptions are global for structural reasons that do not apply here. Deliberate suspension is a different need and gets its own switch in ADR 0017.

A trial rule contributes nothing to an evaluation: no Outcome, no message, no ordering slot. It is therefore orthogonal to `action` rather than a value of it, which also keeps trial out of the Outcome model. `handrail test` mirrors this exactly, down to exiting 0 where a non-trial block would exit 2, because a dry-run surface that disagrees with the engine is worse than none. One exclusion follows rather than being decided separately: degradation never applies, since a trial rule requests neither blocking nor injection and there is no capability to substitute for.

The record is the Decision log and nothing else. This is what the two closest comparables already do: secguard's shadow mode writes `would_decide` to its telemetry JSONL and returns no hook output, and dcg's warn path emits nothing at all on Claude-compatible protocols, on the stated ground that silence means no blocking opinion. Claude Code's own rule is that exit-0 stderr reaches the debug log and never the transcript. A trial line is written whether or not the project holds a log grant, which is the one place trial overrides ADR 0015: that grant exists so handrail never records what nobody asked for, and a rule file carrying `trial: true` is the asking.

## Considered options

`action: trial`, a third Action, was rejected because trial is not a third thing a rule does. It is a rule doing its usual thing with delivery cut off, and spelling it as an Action would put a value that gates nothing into the Outcome model and make the Actions non-exhaustive everywhere they are matched on. `enabled: trial`, a tri-state on the existing field, was rejected more narrowly: it does make the meaningless state (a disabled rule on trial) unrepresentable, which is a real virtue, but it changes the type of a field that already ships, that `import hookify` carries through from upstream, and that the disable stub depends on being a bare boolean. One line of validation, rejecting `trial: true` on a disabled rule, buys the same guarantee for less. A `trial:`-only stub shadowing an inherited rule was rejected because a disabled rule needs no matcher while a trial rule still has to match, so the stub would borrow the shadowed rule's matcher, and ADR 0004 refuses field merging. A per-rule expiry (`trial: <date>`), which dcg ships globally as `observe_until`, was rejected because it needs a clock and an answer for what a lapse does, where both available answers, silently starting to block and silently switching off, are surprises from a tool whose spec says failure is never silent. A `doctor` nag for a stale trial was deferred rather than refused: it needs match counts from the Decision log to say anything an operator would act on, and the listing `check` and `doctor` already print is read at the moment the user cares. Trial-by-default for proposed rules was rejected because handrail's out-of-the-box behaviour would then guard nothing until the user returned to promote each rule one at a time. An `import hookify --trial` flag, to cover the one moment when many rules arrive at once, was dropped as redundant once ADR 0017 landed a global trial state that covers it and the other bulk door (trusting a stranger's repo) with no new surface.

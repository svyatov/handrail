# Tiers merge in the engine at event time; sync installs one user-level hook entry per event

The three Rule tiers live in harness-neutral directories: Global in `$XDG_CONFIG_HOME/handrail/` (default `~/.config/handrail/`, on every Unix platform including macOS, following the `gh`/`git` dotfiles precedent rather than `os.UserConfigDir`'s `~/Library/Application Support`); Project-shared in `.handrail/` at the repo root; Project-personal in `.handrail/local/`, which sync keeps out of version control by appending the ignore line to `.git/info/exclude` when missing. The engine discovers the project tiers at the repo root only (`git rev-parse --show-toplevel` from the event's cwd; the cwd itself outside a repo). Tier merging happens inside the engine at event time: sync writes exactly one stable hook entry per event into the harness's **user-level** config (`~/.claude/settings.json`, `~/.codex/hooks.json`) and nothing into project config. Sync is therefore a per-machine act, not a per-project one: once synced, every repo with a `.handrail/` directory is enforced, which is the only arrangement under which Global ("all projects") actually means all projects; it also keeps the entry stable so Codex's hash-based hook trust is approved once, and commits nothing, so teammates without the binary see no breakage. Precedence is most specific wins, Global < Project-shared < Project-personal, and is explicitly not a security boundary. Scanning is recursive with identity = basename; a duplicate basename within a tier is a sync error, and `local/` is excluded from the shared scan. A same-named rule in a higher tier **shadows** the lower one wholesale, with no field merging; disabling an inherited rule is a stub shadow containing only `enabled: false` (a disabled rule is exempt from matcher validation, while present fields are still validated strictly). Because a user-level hook entry means any cloned repo's committed rules would take effect immediately, the Project-shared tier is gated by an engine-side, path-once trust registry (XDG state dir): in an untrusted repo the shared tier is skipped and a one-line notice pointing at `handrail trust` is injected; Global and Project-personal are the user's own files and never gated. Sync prints the effective ruleset annotated per rule with tier, shadowing, and disabling. When several rules match one event, messages are delivered in tier order (Global, Project-shared, Project-personal), then alphabetically within a tier. Claude Code cloud sessions read neither user settings nor a local binary, so they are unenforced in v1.

## Considered options

Harness-side tier mapping (compiling each tier into the harness's corresponding config level) was rejected: Codex has no personal-level config, so tier semantics would become a per-adapter capability, and every sync would rewrite project hook config and re-trigger Codex's hash-based trust prompt. Installing the hook entry in committed project config was rejected (errors for teammates without the binary, trust churn); local project config was rejected (Global rules would fire only in synced projects). Field-level merge was rejected because no single file would show the effective rule. A config-file disable list was rejected as the second vocabulary ADR 0003 already declined. For the trust gate, relying on each harness's workspace trust was rejected (whether user-level hooks are held back in untrusted folders varies by harness), and Codex-style hash trust was rejected (every teammate's `git pull` would re-prompt). Walk-up discovery of nested `.handrail/` directories was deferred to a future monorepo decision, not designed into v1.

# The Advisor recommends native promotion; it never owns native config

The Advisor is the CLI-resident intelligence that recommends promoting a rule to a harness-native mechanism (a Claude Code permission deny, a Codex execpolicy forbidden rule) when the rule's matcher translates exactly. It is recommend-only: it emits the exact native entry, the authoring skill (or a human running the standalone audit) applies it on consent, and the applied entry becomes the user's own harness config, untracked by handrail. The rule always stays active as belt-and-suspenders: the hook path delivers the rule's message (on Claude Code, PreToolUse hooks run before permission evaluation), while the native entry is the fail-closed backstop when a hook fails open or is bypassed. All translation knowledge lives in the Go CLI per adapter, next to the capability matrix, kept current by binary releases; the skill contains zero harness-specific pattern knowledge and only relays. Advice surfaces at rule authoring time and via a standalone audit invocation, never as a per-sync nag: with no advice-taken state, sync could never know when to stop. Eligibility is provably-safe translations only: block rules whose conditions are `starts_with`/`equals` on the shell command (to `Bash(prefix*)` denies and execpolicy prefix rules), `glob`/`equals` on file paths (to `Read`/`Edit` denies), or domain conditions (to `WebFetch(domain:)` denies); `any:` groups only when every branch independently translates; `matches` (RE2) never translates. All tiers are eligible, and the advice must state the scope widening when a project-tier rule promotes to a global native entry. Codex advice carries the caveat that `codex exec --ignore-rules` bypasses execpolicy.

## Considered options

Auto-compiling eligible rules into native entries at sync was rejected: native entries are tier-blind (a user-level deny cannot honor a Project-personal `enabled: false` shadow, and per-machine sync cannot see other repos' shadows), and owning entries inside shared permission arrays demands manifest and garbage-collection machinery for a narrow eligible subset. A per-rule opt-in frontmatter field with sync-managed entries was rejected for the same ownership problem. Retiring the rule once a native entry exists was rejected: the native mechanism delivers no message, and the rule is the cross-harness portable artifact. Putting translation knowledge in the authoring skill as prose was rejected: an LLM regenerating glob patterns is how a deny blocks `git push` instead of `git push --force`. A CLI apply flag was deferred until paste friction proves real. Translating `warn` rules (Claude Code's `ask` matches neither warn nor block semantics) and coarse mechanisms (Codex sandbox modes, `approval_policy`) was rejected as semantically unfaithful or off-scale.

# handrail has one enforcement path, and detects when it is off

_Supersedes ADR 0005._

handrail does not translate a rule into a harness's own permission or execpolicy syntax, in any form: not as a synced entry it owns, not as an entry the user pastes, not as prose in the docs. The `advise` command, the `Advice` and `promotion` types, and the per-Adapter translation knowledge are removed. `doctor` gains a check that handrail's hooks would actually run, and reports a failure when they would not.

The feature was reopened on the belief that a native entry enforces without a process spawn. It does not: PreToolUse hooks fire before permission rules and Sync installs one hook entry per event, so on a matching call the entry is never reached. The argument that survives is that a native deny outlives both documented kill switches, including a `disableAllHooks: true` that any project's committed settings file can set and that silently stops every handrail hook in that repo. That is a real hole and a Promotion is a real thing in it. It is also one hole, it is raised in price rather than closed (a bypass becomes one setting plus one array edit), and the hook path is documented as best-effort and never a boundary.

The deletion rests on four grounds. First, a native entry is a second decider handrail cannot suppress at event time: deny rules are evaluated regardless of what a hook returned, so the entry blocks calls handrail's own engine decided to allow, which contradicts ADR 0012's rule that handrail never invents a block. Second, native entries are tier-blind: a user-level deny cannot honour a Project-personal shadow, and it can never be retracted per repo, because the enforcement state is keyed by Project root (ADR 0017) while an entry is machine-wide. Third, it defends one vector, `disableAllHooks` in a committed file, and raises its price rather than closing it. Fourth, the gap between a rule and its entry widened with every decision since ADR 0005: ADR 0011 made handrail's matcher stronger than Claude Code's, which inverts the "inherits Claude's parser" argument; ADR 0015 gave handrail a Decision log an entry writes nothing to; ADR 0016 gave it trial mode an entry ignores; ADR 0014 gave one event many payloads an entry cannot see.

The feature also cost a translation table per Adapter: eligibility rules, entry spellings, a paste target, a scope declaration and a caveat string apiece, each a place to be silently wrong about a harness whose documentation does not state the answer. Codex already is that case: its hooks and `.rules` are documented as separate features with no stated ordering, so handrail cannot say what a Codex promotion is a backstop against. Cutting support to Claude Code and Codex shrank that table to two entries, and it did not revive the feature, because the four grounds above do not depend on how many harnesses there are.

Ownership was designed in full and rejected on the same grounds: an opt-in `backstop:` field on Global rules only, a manifest in the XDG state dir, Sync as a set difference. Ownership does buy retraction, which pasting never had, and it is the only way to find handrail's own entries again, since a Claude Code plugin cannot contribute permission rules and no settings file supports an import, so the deny array is shared with the user and holds no marker. But retraction is limited to three events (rule deleted, opt-in removed, rule disabled everywhere) and can never be per repo.

The same holds for a filter in front of the hook. Claude Code's `if` field skips the hook process when a call does not match one permission rule, which would save a spawn of about 5 ms on every call it filters out. handrail does not write one, and treats one it finds as a fault. A filter is sound only if it is at least as wide as every rule that can reach the event, and Sync cannot see those rules: it runs once per machine, while Project tiers are read at event time from whichever repo the call runs in, including repos not yet cloned and rules the next `git pull` adds. Even a filter over Global rules alone would be narrower than the rules it serves, because `if` strips no command wrapper and handrail strips several, so `Bash(rm *)` lets `sudo rm -rf /` past a rule that blocks it. A filter would also make every rule change need a re-sync and turn `doctor` into a staleness checker, and it would help one harness only, since Codex has no argument-level filter. Sync's entry therefore carries no `matcher` and no `if`, and its output depends on no rule. `doctor` reports a handrail entry that carries either as a failure, because a hook that runs for some calls fails the same way as one that runs for none, and `handrail sync` removes it.

What replaces the feature is one `doctor` check. handrail cannot defend the `disableAllHooks` vector, so it detects it: `doctor` reports when handrail's hooks would not run (`disableAllHooks` after settings precedence, `allowManagedHooksOnly`, Codex's `[features] hooks = false`) and exits 1.

## Considered options

Keeping `advise` as recommend-only, ADR 0005's design, was rejected because the maintenance argument does not depend on ownership: the translation table is the cost, and recommend-only pays all of it, while the second-decider and tier-blindness grounds hold for a pasted entry exactly as for an owned one. A reduced `advise` with no eligibility engine was rejected as the version that emits a wrong translation. A docs paragraph was rejected as handrail's name on advice it did not check. Replacing the hook with a native entry for matching calls, so the entry is the sole decider and saves a spawn, was rejected because it trades the rule's message, its Decision log line and trial mode for one spawn on the calls a rule fires on by exception.

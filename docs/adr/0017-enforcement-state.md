# handrail can be suspended per project, and says so at the start of every session

Trialling one rule and suspending the whole tool look like the same feature and are not. ADR 0016 refuses a global switch as a way to trial a rule, because it would stop enforcing everything that works in order to try one thing that might not. That reasoning says nothing about the case where switching everything off is the request: a refactor where the rules keep firing, an afternoon of deliberate cleanup, debugging handrail itself. Before this decision handrail's only answer was editing every rule file or removing hook entries, and both are worse than the thing they achieve, since both are easy to leave half-undone.

So there is one switch with three states, `enforce`, `trial` and `off`, and one rule for combining it with a rule's own state: the weaker applies, ordering `off < trial < enforce`. The switch only ever loosens, which means it can be reasoned about without a case table and cannot silently strengthen a rule its author set to trial. `off` skips evaluation rather than evaluating and discarding, both because it is faster and because a suspended guardrail journaling the calls it let through would be recording a decision it did not make.

The state is per project, keyed by Project root in the path-once registry Trust already uses, so suspending during work in one repo leaves every other repo guarded. A machine-wide state exists behind a flag for the case that is genuinely machine-wide, and it applies only where no project state does.

The state does not expire. An expiry was weighed seriously, because the failure mode here is the worst one this project has: a suspension you forget is a project that looks guarded for a month and is not, and `sudo` bounds its grant for exactly that reason. It was refused because it buys a duration format, a clock, and a second way to spell the state, and because it addresses the failure on a timer rather than at the moment it matters. What replaces it is a `SessionStart` notice: every session in a project that is not enforcing opens with the state and its scope. `SessionStart` is already in the core event set, so the notice costs one comparison per session and no hot-path work, and it lands where the user is about to do the work rather than in a command they would have to think to run. That notice is the whole safety story for this feature and is specified as load-bearing rather than as polish.

One limit is documented rather than engineered away: the switch is not a boundary. Anything that can run `handrail mode off` can suspend handrail, which under the project's adversarial threat model includes a prompt-injected agent, for whom this is now the cheapest available disarm. `mode` refuses when a harness session id is present in the environment (`CLAUDE_CODE_SESSION_ID`, `CODEX_THREAD_ID`, both already relied on by the Analyzer), which is a speed bump defeated by `env -u` and is described as one. What limits the damage is that the state is loud at the start of every subsequent session, so an agent that switches handrail off announces it to the user shortly afterwards.

## Considered options

A time-boxed state, dcg's `observe_until`, was rejected above; note that dcg's own is global rather than per rule and appears in their schema, code and changelog but in neither their README nor their configuration docs, which is what an unused feature looks like. An environment variable as the switch was rejected for the reason ADR 0015 already records: the hook runs in the environment the harness inherited at launch, so exporting it in the shell you are sitting in does nothing. Three separate commands (`handrail enable`, `handrail disable`, `handrail trial`) were rejected in favour of one `mode` command with three values, with `on` and `off` kept as aliases because the short form is what people reach for in a hurry. Machine-wide as the default was rejected because it silences the repo you are not looking at. Evaluating normally under `off` and discarding the result was rejected: it costs the hot path for nothing and would write Decision log lines about calls handrail did not decide. Per-door flags (`import hookify --trial`, a trial variant of `handrail trust`) were dropped once this switch existed, since importing or trusting and then running `handrail mode trial` covers both bulk-arrival cases with no new surface. Refusing to implement any global switch, on the ground that nothing in the surveyed field ships a durable one, was rejected because the absence is explained by architecture rather than by principle: every global gate found (Kubernetes `dryRun=All`, ESLint `--quiet`, Semgrep `--error`) is scoped to one invocation, and handrail's hook has no invocation to scope one to.

# handrail never invents a block: what it cannot read, it declares

When handrail cannot answer, it reports and does not enforce. A hook that denied on its own internal failure would be handrail imposing a policy the user never wrote, in a tool whose entire premise is that the user declares the policy, and it would turn any bug in handrail into a wedged harness. So the engine has no fail-closed mode and no hardcoded deny. What it has instead is a way to say so: a give-up is presented on the canonical payload as the `unreadable` field, and a rule the user wrote decides what that is worth. An attacker who can make normalization fail therefore no longer bypasses every rule silently; they trip whatever rule names `unreadable`, and a user who wants fail-closed writes one file to get it.

Reporting means reaching a party who can act. handrail's own failures go to the harness's user-visible warning channel and to the agent's context, both, every time. The agent alone is not enough: a notice that only the agent sees is no notice at all when the agent is what the rule exists to constrain, and Claude Code's `additionalContext` is documented as invisible in the interface while exit-0 stderr reaches only the debug log. Exit-2 stderr on `PreToolUse` is documented as reaching the model as the denial reason; whether the human sees it is not documented, so nothing here rests on it. The agent is still told, because it can already infer a missing block from its call going through, so withholding buys nothing and costs an honest agent the chance to stop. `Stop` and `SubagentStop` are the exception (ADR 0023): there the only way to reach the agent is a continuation, which would be a block handrail invented, so handrail's own notices on those events go to the human alone. ADR 0019 is the general form of this rule: it covers every rule that fires, where this decision stops at handrail's own trouble.

A rule file that fails validation is one of handrail's own failures at event time, whichever check it fails: it is skipped, named on both channels, and sets `unreadable: rules`, the same as one that will not parse. Of a duplicate basename within a tier the first by path is kept, because skipping every copy would drop a guard the user wrote. A Project-shared tier that is not trusted is the exception: its broken files are named only by `check` and `sync`, because naming them on the hook path would let a repository nobody trusted put text it controls into the agent's context. `sync` still writes the hooks over a validation error, because its output depends on no rule, and refusing would leave the whole machine unhooked for one broken file, including a file in a fresh clone the user has not trusted.

The field that failed stays absent rather than holding a marker value, so ADR 0010's rule governs it unchanged and no `not_` condition fires against text handrail invented. `command` is the exception ADR 0024 makes: when a command would not parse at all, the whole line stays a Candidate for positive terms and a `not_` term on `command` matches. A listed shell or Wrapper that runs code the call does not hold literally, and a nesting deeper than four re-parses, also set `unreadable: command`, keeping whatever reading handrail has; a shell call that names a file it cannot read literally sets `unreadable: path` (ADR 0014). Two limits are structural and are stated rather than worked around: a payload that would not parse carries no tool kind, so only a kind-less rule reaches it, and a rule cannot fail closed on the absence of the tier it lives in.

## Considered options

The asymmetry cc-safety-net documents, config errors never block and protection errors always block, was rejected in its literal form: its "always block" half is the hardcoded denial this decision exists to refuse. Its insight survives, because the two failures are still named differently in the notice and only one of them is markable. A sentinel value in the field that failed, secguard's `__deobfuscate_depth_exceeded__` shape, was rejected because it does not fail closed either, since a block rule still does not match a sentinel, while it does make `not_contains` fire against a value nobody wrote, which is a false block bought for no true one. Coercing a non-string value into a string was rejected as a guess about a harness shape that does not exist, with no single right join for the array case. A single boolean marker was rejected for collapsing failures of very different severity: a shell command that would not parse still contributes its whole line as a candidate, so ordinary rules still fire there, which is not the same event as a payload that could not be read at all. An `exists` operator for the catch-all spelling was rejected for the circularity that killed a general `empty:` operator in ADR 0010: `not_exists` would have to mean "absent", which the absent-field rule says never matches in either polarity.

# Name the project "handrail", not "hookify"

The working name "hookify" collided head-on with Anthropic's own `hookify` Claude Code plugin (Anthropic-Verified, ~60k installs, owner of the `/hookify` command namespace), which foreclosed official-marketplace distribution and buried the project in search. The name also fought the domain model: a Rule is the unit of intent, and a hook is only one enforcement backend, one the Advisor deliberately steers away from when a native mechanism is cheaper. We renamed to **handrail**: the safety-rail metaphor carries the pitch (guidance without stopping the agent), and the one name works everywhere: binary, repo, brew formula, plugin namespace.

## Considered options

Eight candidates were availability-checked across npm, PyPI, RubyGems, crates.io, Homebrew, GitHub, and web search (2026-08-15). Rejected as major collisions: **veto** (an active pile-up of same-niche agent-authorization products: Ona's Veto, veto.so, vetoapp.io, a PyPI agent-policy runtime), **redline** (RedLine Stealer malware dominates the term), **bridle** (an active 433-star agent-harness config CLI distributed via Homebrew), **governor** (a 70M-download Rust rate-limiting crate plus several small AI-agent governors). Runners-up: **bylaw** (clean, but `cargo-bylaw`, an architecture-rule enforcement framework, is adjacent on crates.io), **chicane** (means "slow down", not "enforce"; shared with a 464-star React router), **kerb** (reads as Kerberos; an active PyPI LLM toolkit owns it). **handrail** was the cleanest: PyPI, RubyGems, crates.io, and Homebrew formula/cask all free; npm squatted only by a dead 2022 package; no developer-mindshare owner. Known adjacency to monitor: handrails.dev, an AI knowledge-management product.
